Направление 1

Интеллект коллегиальных органов

Структурированный захват решений и поручений по всем заседаниям — с автоматической рассылкой, отслеживанием исполнения и напоминаниями.

Текущая ситуация
Plaud.ai даёт транскрипт, дальше всё вручную. Задачи не извлекаются автоматически. ЦБ указал на неудовлетворительное качество протоколов.
Транскрипция ✓ Трекинг ✗ Рассылка ✗
Направление 2

Реестр регуляторных предписаний

Централизованный учёт всех предписаний от ЦБ, судов и прочих органов — вместо разрозненных Excel-таблиц по подразделениям.

Текущая ситуация
Нет единого источника истины. Дублирующиеся Excel-файлы, нет автоматических напоминаний, нет структурированного учёта ответов.
Excel-трекеры Реестр ✗ Автоматизация ✗
Направление 3

Интеллект входящей корреспонденции

AI-анализ и маршрутизация всей входящей корреспонденции (email, госпорталы, бумажная почта) поверх существующего документооборота.

Текущая ситуация
СЭД отслеживает метаданные процесса, но не анализирует содержимое документов. Маршрутизация и понимание — полностью ручные.
СЭД есть AI-анализ ✗ OCR ✗
Направление 1 · Задачи и результаты

Интеллект коллегиальных органов

1.1
Оценка и настройка Plaud.ai
  • Тест транскрипции на 3–5 реальных заседаниях (RU/AZ/EN/TR)
  • Отчёт по качеству: ошибки, code-switching, пропуски
  • Решение: оставить Plaud.ai или перейти на альтернативу
1.2
Email-MVP: извлечение задач через Claude
  • Email-workflow: Секретарь → Claude → список задач на согласование
  • Шаблон согласования: подтвердить / отредактировать / отклонить
  • Первое реальное заседание обработано end-to-end
1.3
Рассылка поручений ответственным
  • Шаблоны: контекст + дедлайн + инструкция по ответу
  • CC по умолчанию: всё правление + куратор + глава департамента
  • Email-агент настроен и протестирован на реальном кейсе
1.4
Отслеживание, напоминания и эскалация
  • Автонапоминания за T−7 и T−1 до дедлайна
  • OOO: детекция автоответа → уведомление Секретаря → тег замены
  • «Не успеваем»: запрос новой даты → согласование через Секретаря
1.5
Регулярные повторяющиеся задачи
  • Полный список регулярных повесток (предоставляет Секретарь)
  • Автонапоминания: weekly incident report, monthly жалобы, quarterly risk
  • Автовключение в повестку при приближении дедлайна
1.6
Архив заседаний и поиск
  • Excel-реестр Секретаря (с середины 2025) индексирован для поиска
  • AI-поиск: по теме, ответственному, решению, дате, органу
  • Возможность запроса выписки через email-агент

Направление 2 · Задачи и результаты

Реестр регуляторных предписаний

2.1
Инвентаризация предписаний
  • Полный список активных предписаний от ЦБ, судов, других органов
  • Единая структура метаданных: источник, тип, дата, текущий трекер
  • Выявление дублей и пересечений между Excel-файлами
2.2
Проектирование и создание реестра
  • Платформа выбрана ИТ (SharePoint или иное)
  • Структура: источник, тип, ответственный, срок, статус, документы
  • Реестр развёрнут и доступен авторизованным пользователям
2.3
Назначение ответственных и сроков
  • Процедура: кто назначает, в какие сроки, как фиксируется
  • Каждое предписание — именной ответственный и дата исполнения
  • Интеграция с Outlook Calendar для ответственных
2.4
Прикрепление доказательств и ответов
  • Механизм загрузки ответных документов к каждому предписанию
  • Журнал аудита: кто, когда, какой документ загружен
  • Версионирование: все версии ответа сохраняются
2.5
Напоминания и эскалация
  • Автоматические напоминания за T−14 и T−3 дня
  • Эскалация руководителю при отсутствии ответа за T−3 дня
  • Дашборд: статус всех активных предписаний одним взглядом
2.6
AI-проверка полноты ответа
  • Claude сравнивает ответ с исходным предписанием
  • Флаг: «полный» / «выявлены пробелы» с конкретным пояснением
  • Проверка обязательна как gate перед внешней отправкой
Направление 3 · Задачи и результаты

Интеллект входящей корреспонденции

3.1
Приём по всем каналам
  • Email: мониторинг входящих на выделенный ящик секретариата
  • Портал ЦБ: процедура регулярной проверки и выгрузки новых писем
  • Физическая почта: OCR-конвертация в текст (инструмент определяет ИТ)
3.2
AI-анализ и резюмирование
  • Извлечение: отправитель, тема, тип запроса, срок ответа
  • Краткое резюме на русском для Секретариата (1–2 предложения)
  • Структурированная карточка письма в системе учёта
3.3
Предложение ответственного
  • Логика маршрутизации по типу запроса и отправителю
  • AI-рекомендация с обоснованием → подтверждение Орготделом
  • Целевой KPI точности: ≥ 80% по итогам пилота
3.4
Интеграция с СЭД
  • Оценка интеграционных возможностей существующей СЭД
  • Согласованный дизайн интеграции совместно с ИТ
  • Тестовый workflow: письмо → парсинг → карточка в СЭД → назначение
3.5
Отслеживание и мониторинг SLA
  • SLA по типам корреспонденции согласованы с Орготделом
  • Автоматические напоминания при приближении к SLA
  • Эскалация при нарушении SLA: уведомление руководителю
3.6
Журнал аудита и отчётность
  • Сквозная запись: получение → разбор → назначение → ответ
  • Еженедельный отчёт: статус, просроченные, новые поступления
  • Готовность предоставить выписку по запросу ЦБ

Фаза 1 · Недели 1–4

Направление 1 — Email MVP

Результаты
  • Email-workflow: Секретарь отправляет транскрипт Plaud.ai → Claude извлекает список задач → возвращает на согласование
  • Секретарь утверждает, редактирует или отклоняет каждую задачу перед отправкой
  • Автоматическая рассылка поручений: контекст, дедлайн, инструкция по ответу
  • Правление и куратор в CC по умолчанию по каждому поручению
  • Автонапоминания за T−7 и T−1 до дедлайна
  • 3 реальных заседания обработаны end-to-end до закрытия фазы
Веха
В1 — Email MVP запущен
Первое реальное заседание обработано полностью через email: транскрипт → задачи → рассылка → напоминания. Без ручного формирования списка задач Секретарём.
Почему первой
Транскрипция уже есть (Plaud.ai). Инфраструктура — только email. CB-давление максимальное именно по заседаниям правления. MVP реализуем за 2–3 недели без новых систем.
Фаза 2 · Недели 3–8

Направление 2 — Реестр предписаний

Результаты
  • Инвентаризация всех активных предписаний из Excel-таблиц по всем подразделениям
  • Единый реестр развёрнут (платформа TBD ИТ — SharePoint или иное)
  • Все активные предписания мигрированы; Excel-трекеры выведены из оборота
  • Процесс назначения ответственных и сроков при регистрации каждого предписания
  • Outlook-напоминания за T−14 и T−3; эскалация руководителю при просрочке
  • Механизм загрузки ответных документов с полным журналом аудита
Веха
В2 — Реестр запущен
Все активные предписания в единой системе. Ни одно не может быть пропущено без видимости на уровне руководства. Excel-трекеры официально выведены из оборота.
Зависимости
Выбор платформы — решение ИТ. Инвентаризация требует участия всех подразделений, ведущих свои трекеры. Необходимо формальное решение об обязательности нового реестра.
Фаза 3 · Недели 7–14

Направление 1 — Полная версия

Результаты
  • Оценка качества Plaud.ai на реальных данных; решение о замене или настройке
  • Обработка OOO: детекция автоответа → уведомление Секретаря → тег заместителя в цепочке
  • Обработка «не успеваем»: AI запрашивает новый дедлайн → согласование через Секретаря
  • Список регулярных повесток от Секретаря автоматизирован (incident, жалобы, risk)
  • Excel-реестр Секретаря (с середины 2025) индексирован для AI-поиска по протоколам
  • AI-проверка полноты ответа по предписаниям активирована как gate перед отправкой
Веха
В3 — Направление 1 полностью
Email-система обрабатывает все кейсы: штатные поручения, OOO, срывы дедлайнов, регулярные повестки. Архив заседаний с 2025 доступен для поиска.
Ключевой риск
Качество транскрипции Plaud.ai для смешанных языков может быть недостаточным. Если оценка в п. 1.1 выявит существенные ошибки — потребуется замена, что сдвигает фазу.
Фаза 4 · Недели 12–20

Направление 3 — Корреспонденция (пилот)

Результаты
  • Мультиканальный приём: email, портал ЦБ, физическая почта через OCR
  • AI-парсинг каждого письма: отправитель, тема, тип, срок, резюме
  • Рекомендация ответственного → подтверждение Орготделом
  • Оценка СЭД: интеграционные возможности, согласованный дизайн с ИТ
  • Отслеживание статуса ответа с SLA-мониторингом в рамках пилотного канала
  • Точность маршрутизации ≥ 80% — условие перехода к полному развёртыванию
Веха
В4 — Пилот корреспонденции
AI-слой работает для определённого подмножества каналов. Точность маршрутизации проверена. Полный запуск гейтируется результатами пилота и готовностью интеграции СЭД.
Ключевой риск
Существующая СЭД может потребовать переработки перед AI-интеграцией. Фаза начинается с оценки инфраструктуры. При выявлении существенных изменений — сроки сдвигаются.
Фаза 5 · Недели 18–26

Единая интеллектуальная платформа

Результаты
  • Единый дашборд: все задачи, сроки и статусы по трём направлениям
  • Сквозной поиск: по заседаниям, предписаниям и корреспонденции одновременно
  • Межнаправленные связи: решение заседания → предписание → ответное письмо
  • AI-база знаний из архива заседаний: история решений и обоснований
  • Управленческая отчётность: compliance, просроченные, исполнение поручений
  • Оценка перехода с облака на собственную инфраструктуру
Веха
В5 — Платформа v1
Интегрированная платформа с полной видимостью по управлению, регуляторным обязательствам и корреспонденции. Секретариат и руководство работают из единого интерфейса.
Примечание
Фаза 5 — целевое состояние, не точка отсчёта. Объём и сроки уточняются по результатам Фаз 1–4. Решение о переходе cloud → on-premise принимается в конце Фазы 4.
